# Minimum review-packet validation — 2026-10-07

The independent-review packet now includes a hash of `review_cases.jsonl` and a `final_gold_json` adjudication column for corrected gold. The new `scripts/validate_minimum_review.py <packet-directory>` command reads the packet and reviewer sheets without changing them. It reconstructs all cases and source metadata from the current checked-in datasets, checks exact case and assignment sets, requires different IDs for the two assigned reviewers, validates decisions, notes and UTC timestamps, and requires adjudication after the assigned reviews. A final `accept` requires all assigned reviewers to have accepted; a disagreement can be resolved with a complete `revise`, `reject`, or `needs_context` decision.

Corrected gold must satisfy the fields and types consumed by its suite. It may add or remove optional fields relative to the original gold. Multi-turn intent and core cases retain turn-level checks. This is structural validation only: it cannot determine whether the evidence supports a proposed correction, prove that entered reviewer identities are independent humans, or promote any case into a leakage-safe locked set. The output always sets `ready_for_locked_split=false` and `locked_release_pass=false`.

The current ignored packet `evals/review_packets/20261007T102937Z/` contains **163 development cases**, including **70 critical** and **89 second-review assignments**. The validator returned `pending`, zero completed reviews and zero accepted cases. An earlier 163-case packet lacking the new hash and final-gold column also returned `pending` because every source case still matched. Older packets whose underlying datasets changed are reported invalid and should be regenerated; completed reviewer sheets should be preserved separately before doing so.

The final review found missing terminal checks in revised intent dialogue gold and skipped per-turn checks in revised core gold; both were reproduced and fixed.
