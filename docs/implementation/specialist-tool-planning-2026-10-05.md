## Runtime behavior

- Order plans contain only zero to two unique `get_order`/`track_shipment` names. Strict schemas reject write tools, duplicate names, additional arguments, identities, and other order references. The runtime closure supplies the authenticated reference to Commerce MCP; every server tool still verifies ownership.
- A status-only task can query just the order and cite its owned, current version. Shipment tasks require the actual selected owned package; a status finding cannot satisfy a shipping task. Valid empty or insufficient plans expose missing evidence. Public incomplete markers contain no fabricated facts.
- Policy plans contain zero to two unique bounded queries. Original question scope is checked before model rewriting; each query is anchored to that scope, and the runtime supplies the immutable bundle. Exact clause bodies/IDs/window/version are independently checked at merge.
- Technical planner failures use deterministic read plans. Unknown model usage and technical retries still count in the shared resource account. A three-attempt parallel-planning regression verifies safe handoff and zero business writes when the fourth call is denied.
- Local ORM reads remain serialized by the reviewed Session lock. Model and MCP I/O occur outside it. Recorded tool counts reflect selected local reads and actual attempted MCP calls, including partial transport failures.
- Sequential mode allows up to twenty seconds for the dispatch's two queued tasks, with each invocation limited to ten seconds and the whole request still governed by its shared budget (default twenty-five seconds). Parallel tasks retain ten seconds from dispatch. A controlled-clock regression verified six seconds of policy work plus eight seconds of queued order work; the separate late-result rejection regression remains green.
- A focused independent reviewer found a status-display bug when both order tools were selected. Both mode regressions failed before the fix. Answer assembly now follows the server-requested task scope and displays order status even when additional package evidence was collected.

Model, permission, money, and approval boundaries are unchanged. Natural-language synthesis and safe semantic retrieval are separate unfinished work.
