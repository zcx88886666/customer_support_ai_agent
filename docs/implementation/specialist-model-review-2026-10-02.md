# Bounded specialist model review — 2026-10-02

The policy and order specialists now make an optional structured GPT-4o-mini review of evidence already gathered from the server's read-only policy retrieval or authenticated Commerce MCP tools. The model sees short, aliased evidence references such as `e1`; it does not receive raw customer/order IDs, auth tokens, payment fields, or the complete checkpoint. The ordered references are mapped back to server-verified source IDs. Unknown, duplicate, or malformed model references are discarded. The complete factual evidence set remains in each `SpecialistFinding`; only policy citation order may change.

The server still validates the finding's task ID, plan revision, customer order ownership, source version, clause IDs, exact order/shipment facts, and model-reviewed IDs before using it in an answer. A model review is never authorization for a return or refund. Model errors preserve the verified read-only finding and deterministic answer. Without `OPENROUTER_API_KEY`, specialists retain the no-key deterministic path.

One isolated synthetic composite case (`包裹没到能退吗`, `demo-order-02`) returned `status=answered`, two findings, two successful model reviews, and the required unreceived-delivery explanation. The same check then passed through the rebuilt Docker OIDC API with a signed Keycloak customer login and Commerce MCP reads. The Python suite passed **32 tests** after this change. A unit check confirmed aliased evidence contains no raw source ID, and a forged model-reviewed source ID is rejected. This is an initial connectivity and contract check, not a larger quality or cost benchmark. Free-form model synthesis, tool selection, and paired locked evaluations remain open.
