# Core-business minimum development run

On 2026-10-04, the conversational core-business development dataset reached **30 cases across 30 terminal workflow families**. Every case sends at least one customer Agent turn before business actions. Three cases have two Agent turns and check the intermediate read-only state. The action mix includes approved and rejected refunds, failed inspection, stale proposals, wrong quantity, premature/duplicate/conflicting warehouse and approval actions, role denials, idempotency, overcommit, wrong item, and a partial-quantity refund. All cases are synthetic, author-written, `split: dev`, and `review.status: pending`; all 30 are marked critical. The shared `direct_return` template and frequent reuse of the same demo order make this a development set, not an independently separated locked set.

The final isolated SQLite mock run is ignored `evals/reports/20261004T114613Z-core-80bf5f/`: **30/30 pass**, zero incomplete, zero critical failures. The final real Keycloak/OIDC plus fresh migrated PostgreSQL run is ignored `evals/reports/20261004T114629Z-oidc-04139f/`: **30/30 pass**, zero incomplete. Each OIDC case used its own synthetic database and a separate refund worker process. A single seed timestamp was recorded across the OIDC run; the application wall clock still advances. The new OIDC report includes an HTML table, prompt-release hashes, the dataset hash, scorer version, and case rows.

The full Python suite passed **114/114**. One new scorer mutation disabled the worker in a partial-quantity case; the terminal ledger and return-status checks rejected it. `git diff --check` passed. The `summary.json` files report `v6_minimum_cases_met=true` for the raw core count and `release_gate_pass=false`. The 30-case count does not prove independent gold quality or broad multi-turn coverage.

Next gates for v6's minimum runnable evaluation: expand intent cases beyond route labels to clarification/slot/Replan gold, prepare independent reviews of all critical cases, and create a grouped locked split. The existing smoke, policy-retrieval, and collaboration development counts are already at or above the minimum raw counts, but their gold also lacks independent review.
