# Failed-inspection human ticket — 2026-10-06

A warehouse inspection marked `passed=false` already put the return in `exception`, but left no work item for a person. It now creates one open ticket in the same transaction. The ticket has a unique foreign key to the return, the owned order/customer, a warehouse message with the inspection note, and an audit event. Replaying the failed inspection returns the existing inspection and creates no second ticket. An older failed inspection with no ticket is backfilled by the additive Alembic migration; unrelated tickets keep their state.

The customer sees the linked ticket in **My tickets** and can message it. A supervisor assigns it to a support actor; only that assigned actor can respond and resolve it. Both the list and detail API and the web page show the return ID. `GET /tickets?offset=N` returns newest-first pages of at most 100, and the web page can load older pages; the additive `created_at` migration gives existing tickets a timestamp. Ticket resolution leaves the return in `exception`. A failed inspection still blocks a refund proposal, supervisor refund approval, and the ledger. The ticket lets a person investigate and explain the case; a policy for reversing an inspection or granting an exceptional return remains separate work.
