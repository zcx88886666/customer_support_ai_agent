# Human ticket queue status and stable paging — 2026-10-06

`GET /tickets` now accepts `status=all|open|resolved` after applying customer/assigned-support/supervisor visibility. The default remains `all`. The API also accepts a paired `before_created_at` and `before_id` cursor and includes `created_at` in each row. It orders by `(created_at DESC, id DESC)`; the cursor selects rows strictly after the last displayed ticket, so resolving a ticket from an earlier page cannot shift and hide an older open ticket. Legacy `offset` remains available to callers, but the web UI uses the cursor. Invalid status or a partial cursor returns 422.

The web ticket panel has an All/Open/Resolved selector. Customer view starts at All; support and supervisor views start at Open. Filter changes invalidate older list responses, and support actions reload the currently selected filter even if the user changes it while the action is in flight. Resolved tickets remain available through the selector. The work changes queue visibility only; ticket ownership, assignment, resolution, returns, and refund gates are unchanged.
