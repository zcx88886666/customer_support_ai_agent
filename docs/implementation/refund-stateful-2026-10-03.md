# Refund stateful safety checks — 2026-10-03

The new [test module](../../tests/test_refund_stateful.py) runs 100 generated action sequences against a fresh synthetic SQLite database per example. It varies receipt, passing or failed inspection, proposal creation, approval or rejection, issuance, and retry order. Three explicit examples force a successful issue and retry, a rejected proposal, and a failed inspection. After every committed action or rejected invalid transition, the test independently checks that the ledger and issuance audit counts agree and never exceed one, refunded counters match the ledger, the amount stays within the paid balance, and any ledger has a passing inspection and supervisor approval. The amount is checked against the cumulative paid-allocation formula. A separate test changes the order version after approval and then changes the approved proposal amount; each attempt to issue is rejected with zero ledger rows.

Actual result: `pytest -q tests/test_refund_stateful.py` passed **2 tests**; the full Python suite passed **43 tests**. The generated sequences exercise SQLite transaction behavior and business invariants; the separate [PostgreSQL worker recovery check](refund-worker-recovery-2026-10-03.md) covers overlapping real row locks. This is a development property test, not a human-reviewed locked evaluation set or a mutation-score measurement.
