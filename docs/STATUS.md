## Current snapshot

- Git was initialized; the initial implementation commit is `cd94ed7` and the local Prompt catalog commit is `ed6f457`. [release-v1](../prompts/releases/release-v1.json) locks the catalog commit and every catalog SHA-256. A complete Git bundle was verified and restored to a separate `/tmp` checkout at `cd94ed7`, where PromptRegistry accepted the release. The catalog, not Langfuse Cloud, supplies runtime Prompt text.
- A FastAPI/SQLAlchemy after-sales service, Alembic migrations, a LangGraph parent graph with read-only policy and order specialist subgraphs, a no-key mock mode, OIDC verification code, a Commerce MCP service, a controlled refund worker, Next.js UI, and Compose definitions are present.
- Local checks passed: **66 Python tests** (including 1,000 generated refund allocations, [100 generated refund action sequences](implementation/refund-stateful-2026-10-03.md), [adversarial scorer checks](implementation/scorer-mutation-2026-10-03.md), [four cross-role terminal-state cases](implementation/business-eval-2026-10-03.md), [memory A/B scorer checks](implementation/memory-ab-2026-10-03.md), signed OIDC/MCP checks, model evidence source validation, [clarification expiry and task scope](implementation/clarification-2026-10-02.md), [bounded order/policy Replan](implementation/replan-2026-10-02.md), [specialist conflict retry and verified evidence reuse](implementation/specialist-conflict-2026-10-03.md), [multi-package ownership and clarification](implementation/package-selection-2026-10-03.md), [historical policy rollback](implementation/policy-rollback-2026-10-02.md), deadline alerts, a cross-role HTTP refund workflow, checkpoint turn isolation, strict model schema validation, and telemetry filtering/masking/usage), **25 unique synthetic smoke cases / 28 executions** under `smoke-v2`, a **Next.js production build**, **four Playwright role views**, and an isolated [OIDC browser return-to-refund journey](implementation/browser-workflow-2026-10-02.md). A [redacted smoke summary](implementation/mock-smoke-2026-09-29.json) is committed; the full local report is generated under ignored `evals/reports/<run_id>/`.
- The synthetic generator produced and independently validated **100,000** and **1,000,000** orders, with zero violations reported by its CSV validator. The complete 100,000-order world was imported by `COPY` into temporary PostgreSQL 16 in 6.508 seconds. The million-order world was imported into an isolated Docker PostgreSQL 17 database in **122.533 seconds**; six database quality checks reported zero violations before and after a [measured 20/50/100-user no-key API load](implementation/million-order-load-2026-10-02.md). See also the [measured data report](implementation/data-generation-2026-09-29.md) and [PostgreSQL integration report](implementation/postgres-integration-2026-09-30.md). Generated CSVs remain ignored.
- A real PostgreSQL 16.15 server with pgvector 0.6.0 passed clean migrations, a vector operation, the cross-role refund flow and retry, and the 100,000-order import. Docker Compose also ran with PostgreSQL 17.11 and pgvector 0.8.6: migrations, 25-order seed, chat, cross-customer denial, refund ledger, API restart, and OTel→Jaeger trace passed. The new [PostgreSQL policy search](implementation/policy-search-2026-10-02.md) indexed four active clauses, passed live draft indexing and bundle isolation, and rejected a stale index. A single live OpenRouter GPT-4o-mini structured-intent request passed after correcting the strict JSON schema; the key remains only in an ignored local file. See the [model integration report](implementation/openrouter-integration-2026-10-02.md). Langfuse US authentication, six prompt mirrors, dual trace export, masking, generation usage/cost, and a setup score passed; see the [Langfuse report](implementation/langfuse-integration-2026-10-02.md). Keycloak code+PKCE login, authenticated MCP reads and agent calls, cross-customer/role denials, and four real-browser role views passed; see the [OIDC/MCP report](implementation/oidc-mcp-integration-2026-10-02.md). Broader real-model evaluations and write-flow load tests remain open.
- An isolated Docker PostgreSQL 17 [refund worker recovery check](implementation/refund-worker-recovery-2026-10-03.md) forced two workers to wait on one order lock. Both observed one ledger, one issuance audit, and one balance change. A flushed but rolled-back second refund was recovered by a new worker run; a separate worker process issued nothing further.
- Two [isolated OIDC browser exception journeys](implementation/browser-exceptions-2026-10-03.md) passed: failed warehouse inspection could not create a proposal, and an intervening return made the old proposal unapprovable until regeneration and fresh supervisor approval. Database checks found zero ledger rows before the worker and one correct row afterward.
- The live 30-second Docker worker loop delivered one due-soon and one overdue alert into an [isolated PostgreSQL database](implementation/deadline-delivery-2026-10-03.md), each with one audit event and no refund ledger. A later loop delivered no duplicate alerts.
- A synthetic order specialist conflict triggered one bounded retry through PostgreSQL `PostgresSaver`; the unchanged policy finding was revalidated and reused, and the order specialist reran. Forged policy clause text is rejected; persistent conflicts hand off. See [conflict report](implementation/specialist-conflict-2026-10-03.md).
- A temporary worker container was [force-killed and restarted](implementation/worker-container-restart-2026-10-03.md) after committing an isolated synthetic refund. The new process issued none; PostgreSQL kept exactly one correct ledger and issuance audit.
- An owned two-package order triggered clarification, then answered only for the selected package through an [isolated real OIDC API and Commerce MCP browser journey](implementation/package-selection-2026-10-03.md). A foreign package ID was rejected in Python tests; automatic return eligibility for split deliveries remains unsupported.
- The [database-first `smoke-v2` scorer](implementation/scorer-mutation-2026-10-03.md) rejects fabricated return submissions, unapproved ledger entries, unsupported refund claims, and forged or foreign evidence in adversarial tests; all 28 smoke executions still passed.
- A [four-case business runner](implementation/business-eval-2026-10-03.md) replayed customer, warehouse, supervisor, and worker actions across committed HTTP requests in isolated mock-auth databases. All terminal-state cases passed, and a disabled-worker mutation failed the gate as expected.
- The [business v2 development suite](implementation/business-mutation-2026-10-03.md) added unconfirmed-return and expired-window denials, then passed 6/6 isolated HTTP/worker terminal cases. Nine named application fault injections were all detected by their paired case/scorer (9/9 on this targeted set); this is not a general mutation coverage claim.
- A [three-case paired GPT-4o-mini development run](implementation/paired-model-2026-10-03.md) passed in both modes (3/3 each), with 12 provider calls and $0.0007164 combined provider-reported cost. The small sample tied on quality; the measured median latencies are not a general improvement claim.
- A [40-story isolated memory A/B](implementation/memory-ab-2026-10-03.md) passed 40/40 on PostgresStore and 20/40 on Mem0 OSS. Mem0 retained ten old corrected preferences and ten withdrawn utterances in its local SQLite history, so it remains offline. PostgresStore passed seven authenticated mock HTTP/rollback/restart/isolation checks in isolated PostgreSQL. The rebuilt Docker API started healthy with the guarded adapter, and a real OIDC check passed four profile/role/isolation/restoration checks. The local SQL profile table retains revoked rows, while the application and PostgresStore no longer retrieve them.
