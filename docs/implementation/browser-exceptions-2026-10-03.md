# OIDC browser exception and stale-proposal journeys — 2026-10-03

Two additional Playwright journeys ran against a fresh `resolveai_browser_exceptions_20261003` PostgreSQL 17 database through a temporary OIDC API on localhost port 8003. The live demo database was not changed. Browser requests were redirected to the isolated API; Keycloak still supplied real signed role tokens.

The first journey submitted a return for synthetic order 06, recorded warehouse receipt, failed inspection, and tried to generate a rule proposal. The API returned 409 and the supervisor's pending list contained no proposal for that return. The second journey used order 03, which has three purchased units. It submitted and inspected one unit, created a proposal, then submitted another unit for the same order. That changed the order version. The supervisor's approval of the old proposal returned 409. The warehouse generated a new proposal; the old one became stale and the supervisor approved only the new one.

The first Playwright attempt failed because `getByLabel("原因")` matched both the reason input and the confirmation checkbox. The locator was narrowed to the textbox. The rerun passed **2/2 browser tests** in 5.2 seconds. The Next.js production build and TypeScript check passed.

The database verifier checked before worker execution: failed return=`exception`, old proposal=`stale`, new proposal=`approved`, no approval on the old proposal, and **zero ledger rows**. After one controlled worker run, the new proposal was `issued` with **one ledger row** for its calculated amount; the failed return and old proposal had none. The browser IDs are stored in ignored `.local/browser-{exception,stale}-result.json` for this verifier. See [the test](../../apps/web/tests/exceptions.spec.ts) and [database verifier](../../scripts/verify_browser_exceptions.py). The temporary API was stopped after verification.

To rerun, start a fresh isolated OIDC API as described in the [main browser workflow report](browser-workflow-2026-10-02.md), then run `BROWSER_FLOW_API_URL=http://localhost:8003 npx playwright test tests/exceptions.spec.ts --workers=1` from `apps/web` with Chrome configured. Run `python scripts/verify_browser_exceptions.py`, `python -m resolveai.worker`, then `python scripts/verify_browser_exceptions.py --after-worker` with `DATABASE_URL` targeting the same isolated database and `.local` mounted read-only. These tests cover one exception and one order-version change; they do not cover every warehouse dispute or policy mutation.
