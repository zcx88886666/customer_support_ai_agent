# Web Agent return action — 2026-10-07

The customer return form now has **通过 Agent 提交退货**. It stays disabled until the customer has loaded an item and checked the existing confirmation box. The action sends that order, first displayed item, quantity, reason, confirmation, stable thread ID, and request key to `/chat` with a return-request message. It shares the form's key with direct `POST /returns` and explicit review submission, so an exact retry or route switch resolves to the same committed outcome. An eligible response shows the return ID and states that no refund has been issued; `human_review` shows the ticket ID, refreshes the owned ticket queue, and states that no return or refund has been created. Other Agent results are shown without claiming a return was submitted. Actor and form changes invalidate in-flight results before they reach the page. Starting an order load disables the old form; changing order, item context, quantity, or reason revokes confirmation and clears the old displayed result. Background ticket refreshes cannot erase a newer notice.
