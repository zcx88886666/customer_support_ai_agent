# Essential Langfuse export policy — 2026-10-06

The development stack previously sent every `resolveai.agent` and FastAPI span to Langfuse whenever project keys were configured. That included routine API and worker activity with little value for agent diagnosis or evaluation.

The API now marks only `/chat` and `/chat/stream` request roots for normal Cloud export. The exporter selects that root plus the project's model-generation, specialist, request-resource, and Commerce MCP spans. An evaluation run can opt in to non-chat request roots with `LANGFUSE_EXPORT_EVAL_TRACES=1` and valid run and case identifiers on each request. The Docker worker no longer receives Langfuse keys. Local OTel/Jaeger still receives its full configured span stream, and the database audit remains authoritative. The export decision is attached at span creation because the installed Langfuse processor chooses its application root when a span starts.

The test first failed at import because the request policy did not exist. Independent review then found a missing streaming route and a late application-root attribute; the streaming regression failed before the fix, and an actual Langfuse processor test now checks parent-root marking. Final `tests/test_telemetry.py` passed **4/4**, the full Python suite **265 tests with four optional skips**, the no-key minimum **7/7 suites** with its locked gate still false, and `docker compose -f infra/compose/compose.yaml config --quiet` passed. The previous Cloud integration and 28-case reconciliation predate this narrower exporter; a fresh real Cloud reconciliation has not been run. No OpenRouter or Langfuse API call was made for this change.
