# Chat return review — 2026-10-07

The confirmed return branch in `/chat` now uses the domain's `submit_return_or_review` decision. Eligible requests still create a `return_requested` row. A confirmed owned request that fails the configured policy window, product exception, delivery verification, or supported-order check creates one human-review ticket and returns `status=human_review`, `ticket_id`, and `reason_code`. It does not create a return request or refund ledger. Ownership, confirmation, quantity validation, and cross-path idempotency remain in the domain layer. Support assignment and resolution still do not authorize a refund.

The ticket fingerprint now covers the confirmed order, item, quantity, and normalized reason. Chat plan revision is internal routing state and can change on an exact replay. Existing tickets whose fingerprint included revision 1–4 are accepted for the same business request; a changed reason or other request field remains a conflict. This was needed because a retry after a clarification turn reset the chat revision from 2 to 1 and previously failed with `idempotency_conflict`, even after ticket resolution.

The development smoke gold for undelivered, product-exception, and expired-window chat requests now expects a persisted review ticket. Core business gold adds a three-turn clarification → ticket → retry case. The core scorer captures the committed ticket before terminal actions and checks the returned ID against customer, order, review key, reason topic, customer message, and the ticket's matching audit details. The isolated real-OIDC/PostgreSQL runner uses the same scorer. All labels remain author-written development gold pending independent human review.
