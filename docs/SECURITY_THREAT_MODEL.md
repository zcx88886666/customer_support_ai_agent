# ResolveAI development threat model

> Reviewed against the synthetic v6 implementation on 2026-10-09. This is a development threat model, not a production security certification. The [verified status](STATUS.md) distinguishes exercised controls from open release gates.

## Assets and trust boundaries

The protected assets are customer order and ticket data, supervisor decisions, return and refund ledger state, policy bundles, Graph checkpoints, structured preferences, API credentials, and evaluation gold. The PostgreSQL ledger and audit records are authoritative for simulated money actions. An LLM answer, specialist finding, Langfuse score, Redis message, or browser state is never approval evidence.

The main boundaries are browser → API, API → PostgreSQL, Agent → read-only Commerce MCP, API/Worker → Redis, API → OpenRouter, and API → Langfuse/OTel. The default Compose mock actor controls and PostgreSQL `trust` setting are for a **local loopback development stack**. They do not establish a shared-environment authentication boundary. Use the Keycloak OIDC profile for authenticated demonstrations; a production deployment would need separate network, database-authentication and secret-management review.

## Threats, controls, and remaining proof

| Threat | Current control and evidence | Remaining proof or decision |
|---|---|---|
| Customer reads another customer's order, shipment, ticket or thread | API and Commerce MCP validate actor and object ownership; real OIDC/MCP checks and browser role journeys are recorded in [status](STATUS.md). | Independently reviewed locked authorization cases and a shared-environment deployment review. |
| Agent or forged specialist causes a refund or uses an approval token | Specialists have read-only tool access; the domain service rechecks receipt, inspection, proposal version, supervisor approval, paid allocation and idempotency. [Refund state tests](../tests/test_refund_stateful.py) and [approval checkpoint tests](../tests/test_approval_checkpoint.py) exercise the boundary. | Locked critical review and broader adversarial source cases. No model output may become a supervisor decision. |
| Stale policy or order evidence produces an unsafe answer | Bundle hashes and index versions are checked; coordinator findings are tied to current order/policy facts and bounded Replan. [Policy tests](../tests/test_policy.py), [agent tests](../tests/test_agent.py) and the [MCP snapshot report](implementation/mcp-snapshot-pre-review-2026-10-08.md) cover development cases. | Human-reviewed relevance gold, historical semantic retrieval calibration and broader contradictory-source cases. |
| Prompt injection in a policy clause, customer text or tool result | Retrieved text is evidence, not an instruction or authorization. The model has no write tool for approval/refund; findings are schema and source validated. | A larger independent injection set and a locked replay. |
| Double issuance after retry, crash or queue duplicate | PostgreSQL transactions, row locks and unique keys guard the ledger; Celery uses late acknowledgement and bounded batches. [Worker recovery](implementation/refund-worker-recovery-2026-10-03.md), [server crash](implementation/postgres-server-crash-2026-10-05.md) and [queue probes](implementation/celery-jobs-2026-10-05.md) record actual replays. | Repeat the new refund batch continuation under an isolated Redis/PostgreSQL fault run before production claims. |
| Sensitive data escapes through model or telemetry export | Local Git prompts and synthetic data are the default. Langfuse export filters to essential chat/evaluation spans and masks sensitive fields; Jaeger has a separate Collector mask. [Essential export](implementation/langfuse-essential-export-2026-10-06.md) and [Cloud reconciliation](implementation/langfuse-essential-reconciliation-2026-10-06.md) record canary checks. | Review any future real-data source and periodically rerun canaries; confirm Cloud retention and billing tier. OpenRouter receives input only when live-model mode is enabled. |
| Deleted preference remains in online memory or old backups | Revoked current SQL values are blanked and PostgresStore deletion/isolation is tested. Mem0 failed the 40-story correction/deletion gate and remains offline. [Memory report](implementation/memory-ab-2026-10-03.md) and [erasure report](implementation/memory-erasure-2026-10-03.md) contain evidence. | Decide backup/export retention and deletion handling before claiming historical erasure. |
| Evaluation gold leaks into the Agent or a development result is presented as a release result | JSONL gold stays in local runner/scorer; review packet checks hashes, reviewer assignments and adjudication. Grouped split preparation refuses current connected development families. [Review packet](implementation/minimum-review-packet-2026-10-04.md) and [review criteria](implementation/eval-review-criteria-v3.md) define the contract. | Independent human labels, distinct case families, frozen locked run and paired comparison. Software cannot prove reviewers worked independently. |
| A queued bulk job writes outside its data root or publishes partial CSVs | Bulk generation accepts only named profiles and safe output names, stages files in the ignored data root, validates rows and hashes, then publishes atomically. [Bulk job tests](../tests/test_bulk_jobs.py) cover retry, contract mismatch, incomplete output and symlink rejection. | Exercise larger profiles only on capacity-approved local storage; generated output is not a backup. |
| Source or credentials leak through the repository | `.env`, generated CSVs, local reports, exports and databases are ignored; Prompt releases are hash locked to Git. | Keep credentials out of commits and review outgoing changes before each push. A Git remote is not an offline backup. |

## Release boundary

The no-key minimum and live synthetic replays are engineering checks. A release claim requires independently reviewed gold, a leakage-safe locked partition, frozen run inputs, zero critical safety failures in that locked run, and reconciliation of the local database/audit result with any exported trace or score. The current [status](STATUS.md) records that this gate is still false.
