# Essential Langfuse reconciliation — 2026-10-06

The narrower Cloud filter from the first preview continuation needed a fresh end-to-end check. A full smoke sweep would upload dozens of mock traces, so `run_smoke.py --case-id` now selects one development case and records `scope=targeted`, `targeted_pass`, and `gate_pass=false`. Unknown case IDs fail before any report is made. The regular full suite keeps its existing gate behavior.

The new `scripts/verify_langfuse_essential.py` reads only the three Langfuse settings from the ignored `.env` when they are not already in the environment. It forces mock authentication, clears `OPENROUTER_API_KEY`, selects the `specialists-dev-v1` local Prompt release, and enables full sampling for `smoke-03`. It flushes the SDK, polls Cloud readback for 90 seconds by default, and checks trace/score counts plus one connected chat root and five expected descendants per trace. It refreshes Cloud snapshots that may have arrived partially and records an incomplete local result after transient Cloud failures or timeout. Its JSON result and the redacted Cloud export stay in ignored local report folders. It does not copy credentials into reports.

The first two-execution `smoke-03` run, `cloud-essential-20261006-v1`, initially read back **two scores and zero observations**. A later read completed with **two traces, eight observations and two scores**; this was Cloud ingestion delay, not an export failure. Its observation parents exposed a real filter gap: `http.request` and `agent.request_resources` pointed to FastAPI spans omitted from Cloud. A local full-span tree identified the two necessary parents, `POST /chat` and `fastapi.endpoint`. The second Cloud run, `cloud-essential-20261006-v2`, reconciled **2/2 traces, 2/2 case links, 2/2 scores and 12 observations**, with every parent link connected.

Review of that fix found that the FastAPI server span starts as `POST` before its route name is set and may carry URL or request attributes. The filter now selects it at span start using its exact chat path. The Cloud mask removes URL, request header/body, response content, and server address attributes while retaining the safe canonical route and token counts. An installed Langfuse processor test and an actual local mock request showed **one application root** and a connected six-span tree.

The first one-command run, `cloud-essential-20261006-v3`, passed: **one selected critical development case, two passing single/collaborative executions, zero provider calls, two Cloud traces, 12 observations, two matching task-success scores, two case links, and no missing parent links**. Read-only Cloud metadata checks found none of the forbidden URL, request header/body, or server-address keys on either server observation. The report correctly retained `gate_pass=false`; this is a targeted development check, not independent locked evaluation. Direct script execution initially failed before upload on `scripts` and then `evals` imports; both import paths were fixed.

A code review found that an early Cloud snapshot containing only the chat root and a score could pass the first verifier. The verifier now requires the five expected descendants, refreshes each snapshot until complete, bounds fetch/retry time, and writes a local failure result after timeout or transient errors. The final `cloud-essential-20261006-v4` run passed **2/2 traces, 2/2 case links, 2/2 scores, 12 observations, and two complete six-span trees**, with **zero OpenRouter calls**. The full Python suite passed **274 tests with five optional skips**; the no-key minimum passed **7/7 suites**. The earlier v3 export already contained all twelve observations. These Cloud objects are not an authoritative billable-unit count. Independent human review and the locked release gate remain open.
