# OpenRouter integration check — 2026-10-02

The user placed a regular OpenRouter API key in a repository-root `.env` file. The file had mode `600`, was ignored by Git, and was excluded by `.dockerignore`; its value was not printed or committed. Docker Compose passed it only to the API container. OpenRouter's `/api/v1/key` endpoint returned HTTP 200 and identified it as an inference key.

The first synthetic `POST /chat` fell back to human handoff. A direct diagnostic request returned HTTP 400 from the provider. The adapter had passed Pydantic's schema directly with `strict: true`, leaving an optional field out of `required` and omitting `additionalProperties: false`. The adapter now normalizes the schema to the strict subset documented by [OpenAI](https://developers.openai.com/api/docs/guides/structured-outputs) and [OpenRouter](https://openrouter.ai/docs/guides/features/structured-outputs). A regression test verifies the `RouteDecision` schema, and the Python suite passed 24 tests.

After rebuilding the API container, one live request on the configured `openai/gpt-4o-mini-2024-07-18` model returned HTTP 200, `status=answered`, a structured `shipment_tracking` intent, and a read-only finding that synthetic `demo-order-02` was `in_transit`. The model only selected an intent; order facts came from PostgreSQL. This proves initial connectivity and structured intent extraction, not accuracy across real traffic or a cost benchmark. The model is listed at [$0.15 per million input and $0.60 per million output tokens](https://openrouter.ai/openai/gpt-4o-mini-2024-07-18) at the time of this check. No higher-priced model was used.
