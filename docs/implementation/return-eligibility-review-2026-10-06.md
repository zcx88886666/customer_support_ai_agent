# Explicit return eligibility review — 2026-10-06

The existing `POST /returns` still reports the exact eligibility error and creates no return when rules deny the request. A confirmed owner can now request human review through `POST /returns/review` with the same order, item, quantity, reason and a review-specific idempotency key. The customer UI has a separate **自动退货不适用时申请人工复核** action. The endpoint accepts owned policy-ineligible cases (`outside_window`, `product_exception`, `delivery_unverified`, `unsupported_order`) and creates one owned support ticket with the item, count, customer reason, rule reason, and an audit event. It returns `status=human_review`, `ticket_id`, and `reason_code`. Missing or foreign orders/items remain 404; unconfirmed, invalid-count, already committed-count, and eligible requests create no ticket.

`tickets.review_key` and `review_payload_hash` are nullable, with a unique `(customer_id, review_key)` index. Existing tickets are unchanged. A customer row lock serializes same-customer review requests, including different orders. An exact retry returns the existing ticket after support resolution; changing the request under the same key is a conflict. The additive migration preserves older linked tickets and refuses to drop live review keys. The prior linked-ticket migration continues to protect its own return links. A support answer closes only the ticket: it does not create a return, change policy eligibility, authorize receipt, or create a refund.
