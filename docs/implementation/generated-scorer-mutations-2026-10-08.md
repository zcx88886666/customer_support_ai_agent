# Generated database-first scorer mutation campaign (2026-10-08)

The v6 evaluation plan requires the scorer to reject wrong business outcomes, including unauthorized refunds, wrong ownership, and inconsistent audit facts. The existing business mutation runner contained 21 named application faults. This addition runs a separate generated matrix against the database-first scorer: it creates one valid synthetic approved refund in a fresh SQLite database per fault, changes exactly one persisted field, then scores the same claimed response and gold counts. Each mutation must fail its designated check; a different failing check alone does not count as a kill.

The matrix contains five adjacent event-order inversions across return, receipt, inspection, proposal, approval and issuance; ten ±1 changes to ledger/proposal amount, item refunded cents/quantity and refund-audit amount; five proposal-status, approval, ledger-item and customer ownership changes; and four refund-audit identity changes. The CLI writes an ignored manifest with source hashes and mutation definitions, `case_results.jsonl`, `summary.json`, `report.html`, and isolated synthetic SQLite databases for replay. It never calls a model, Cloud service or Langfuse.

The first campaign found and killed 20 mutations. Four later persisted faults changed the refund audit's actor, entity type, policy bundle or idempotency key. All four survived the old scorer despite an otherwise valid audit. The scorer now binds these fields to the refund worker, approved proposal and issued ledger. The focused scorer and campaign tests passed **18/18**. The test that disables the refund-authorization scorer correctly reports the refund-audit amount mutation as a **survivor**, proving the campaign does not pass only because of its own result formatting. The final CLI report `evals/reports/20261008T154255Z-scorer-mutations-e6adb1` recorded a passing valid baseline and **24 killed, zero survived, zero invalid** mutants. The no-key minimum `evals/reports/20261008T154303Z-minimum-95be47` passed **7/7 suites**, including **371 Python tests passed, five optional skips**. `git diff --check` passed.

Reproduce with `PYTHONPATH=apps/api:. .venv/bin/python -m evals.runners.run_scorer_mutations`. This is synthetic development evidence for the scorer. It does not test application faults beyond the existing 21 named mutants, provide independently reviewed gold, or pass the locked release gate.

A later [cumulative amount check](refund-amount-scorer-2026-10-08.md) added one coordinated underpayment fault, bringing the campaign to **25 killed, zero survived, zero invalid**. The 24-mutant result above remains the earlier milestone.
