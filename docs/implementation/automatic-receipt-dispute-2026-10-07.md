# Automatic receipt discrepancy handoff — 2026-10-07

The ordinary `POST /warehouse/returns/{return_id}/receipt` now accepts an observed count of zero and an optional warehouse note. When the observed count differs from the requested count before receipt, the same database transaction locks the return, creates or reuses its linked warehouse discrepancy ticket, audits the handoff, and moves the return to `exception`. The response is HTTP 202 with `status=human_review`, `ticket_id`, and `return_id`. A matching positive count continues to record a receipt with HTTP 200. The explicit `/receipt-dispute` action remains available and still requires a note.

Exact retries reuse the same ticket, including after a support actor resolves it; a changed count or note conflicts. No receipt, proposal, approval or refund is created for the discrepancy. Support ticket resolution communicates an outcome and does not authorize a refund or reverse the exception. The warehouse page sends its note with the ordinary receipt action and shows the ticket ID from either handoff path.
