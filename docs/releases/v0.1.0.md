# v0.1.0 — first runnable development preview

Date: 2026-10-06. This local Git tag identifies the first runnable ResolveAI version and matches the Python package and API version `0.1.0`. It is a development preview of the synthetic after-sales system, not the locked v6 release gate. The Prompt catalog release named `release-v1` is a separate artifact.

## What runs

- [Docker Compose startup](../../README.md#docker-compose-run-recommended) provides PostgreSQL, Redis/Celery, Keycloak when enabled, the API, read-only Commerce MCP, web UI, local OTel/Jaeger, and an optional Langfuse connection. The no-key mock path needs no external service account.
- Customers can query owned orders and shipments, chat with the coordinator and read-only specialists, and confirm eligible returns. Warehouse staff record receipt and inspection. A supervisor approves a server-calculated proposal before a controlled worker issues one idempotent **simulated** refund. No real payment provider is connected.
- Local Prompt manifests verify catalog hashes. Synthetic fixtures, development evaluations, audit events, and trace/evaluation reconciliation support reproducible demonstrations. Langfuse is optional; local reports and the business database remain authoritative.

## Verification at the tag

Run from the repository root with the setup in [README.md](../../README.md):

```bash
PROMPT_RELEASE=specialists-dev-v1 .venv/bin/python -m pytest tests -q
PROMPT_RELEASE=specialists-dev-v1 .venv/bin/python scripts/verify_minimum.py
npm --prefix apps/web run build
```

On 2026-10-06, the Python suite passed **263 tests with four optional skips**; the no-key minimum passed **7/7 suites**, with `minimum_development_pass=true`; and the web production build completed. The minimum report is local and ignored by Git. Its `locked_release_pass` value is **false** with `review_status=pending_independent_review`.

## Limits

This tag does not claim a production deployment or completed v6 scope. Independent human review and locked gold evaluation remain open. Support tickets can be created, viewed, and assigned, but their response and resolution workflow is incomplete. Real payment execution is outside the project scope. Cloud traces are optional and should be limited to essential agent diagnosis and evaluation; local audit and reports work without Langfuse.
